# 背景介绍：从「线性对话」到「可编排的工作流」——DSH 会话界面的范式重构

> 本文件是项目《dsh-workflow-studio》的背景说明（第 1 版，撰写于规划阶段）。
> 作者：面向 DeepSeek Harness (DSH) 的插件工程；目标账号：GitHub `EaveBounty`。

## 1. 问题：Agent 技术演进，会话界面却仍停在「直白对话」

Hermes / Agent 相关技术这两年高速发展，但整个体系依然围绕着 **Agents** 本身，而承载它们工作的**会话页面却几乎没变**：仍旧是一条条直白的对话气泡，缺少对任务结构、执行进度、产出物与依赖关系的系统性表达。

我们的核心判断是：**对话这种一维线性的信息形态，已经无法承载 Harness（约束/编排）这类本质上是「图」的结构。** 原因有三：

1. **Harness 是约束，不是对话**。一段复杂任务存在明确的阶段、分支、依赖与审核闭环；用「一问一答」的流水去表达这些约束，既容易遗漏，也难回看与复用。
2. **Harness 注入方式简陋**。当前约束主要靠**提示词 + Skill** 注入，导致：上下文一长就**遗忘**、执行中容易**崩溃**、Skill 无法被**完美执行**——因为它们没有被结构化地组织、验证与串联。
3. **外部界面提供了新可能性**。以 DeepSeek 为代表的丰富外部呈现，让「**可插拔式的工作流对话页面**」或「**复杂项目页面**」从设想变为可行——我们有条件彻底重做，而不是打补丁。

因此我们主张：**不再局限于旧的对话模式，而是以 Agent 最初提出的「Plan → Action → Review」模板为骨架，对会话界面做整体改造。**

## 2. 解决方案：三阶段的可编排工作流系统

### 2.1 Plan 阶段 —— 简短对话模块（研究前置）

用户只需输入一个**大致想法**，系统即以**分散的调研姿态**自动开展工作：

- **(a) 调研现有相关知识**：围绕目标做横向调研，摸清问题域。
- **(b) 调查现成技术**：判断是否有可复用/可借鉴的实现，**避免重复造轮子**。

> Plan 内容也可作为节点**嵌入工作流**，但默认不推荐（保持流水线干净）。

### 2.2 Action 阶段 —— 工作流生成

调研完成后，系统支持两种模式**生成工作流**：

- **(a) 自动生成**：由 AI 依据调研结果自动铺好一张工作流。
- **(b) 手动创建**：切换到**全空白画布**，仅保留一个「开始」箭头，其余全部由用户手动拖拽、连线。

工作流页面整体分 **Plan / Action / Review** 多个步骤，交互与呈现遵循：

- **交互**：鼠标悬停节点自动展开其下级环节；节点**点击**才显示详情（Agent 与技能接入、可编辑）。
- **创建**：既支持系统建议，也支持用户自定义。
- **视觉**：以**精简的钻石 / 节点 SVG 图标 + 文字说明**呈现，拒绝纯文字。

### 2.3 节点分类（个案 / 模块）

- **前期调查（Research）**：与**第一性原理**相关。
- **总结（Summary）**。
- **计划模块（Planning）**：按**产品经理 / 功能经理 / 需求经理**等角色层层分解。

### 2.4 Action 模式（执行引擎）

- **普通模式**：单步工具调用（对标 DSH 标准预设 `native` 呈现）。
- **PTC 模式**：**Programmatic Tool Call（程序化工具调用）**——模型写一段 TypeScript 把多步工具调用串成一次执行（对标 DSH 内置 `PTC 模式 / code` 预设的 `tool-presentation mode: code`）。
- **Loop 模式**：带审核条件边的自循环子图（对标 Claude 的 agentic loop：迭代直至 Review 通过）。

### 2.5 Review 阶段 —— 多维度审核模块

参考互联网公司的**测试 / 审核部门流程**，包含测试、审核等核心模块，并按需求连接：

- **审核标准可拖拽设定**：拖入审核节点并连接后，系统**自动猜测审核标准**，不符合预期可手动改写。
- **返工机制（Loop）**：自动生成**返回箭头**，可拖向指定节点表示「从此节点重做」。
- **智能配置**：
  - 多个同类节点 → 依据连线内容**自动调整该节点 Agent 的 Prompt**；
  - 检测到重复的 Review 维度 → 自动生成**维度节点**（如销售审查 / 内容审查），避免机械重复。
- **人机闸门（HITL）**：Review 节点可「自动通过」或「转人工审批」两档。

## 3. 三大差异化创新（经调研确认的空白区）

| # | 创新点 | 现状 | 依据 |
|---|--------|------|------|
| 1 | **动态连线（边携带语义）**：每条线 = 由 LLM 自动生成其「目的/要注入什么」，注入到下游节点 | **无任何主流框架实现**（最近邻：Airflow XCom / n8n 边上映射 / LangGraph 共享 State+reducer） | 编排范式调研 |
| 2 | **多维度 Review 自动去重 + 动态 rubric**：自动去重评审意见、按任务动态生成评审标准（AdaRubric 思路） | 现成系统几乎没有专门实现 | 编排范式调研 |
| 3 | **文件作为可连线资产**：每个节点产出的文件以气泡挂载、可被连线引用注入下游 | 有先例（Prefect Artifacts / MetaGPT 工件）但未系统化 | 编排范式调研 |

## 4. 技术载体

- 这是 **DeepSeek Harness (DSH) 的 Web 插件**（对标官方 `deepseek-harness`，一切皆插件、基于 Cordis）。
- 挂载点：`conversation.view` 新增一个 **`workflow` 视图标签**（与 chat / trajectory 并列，`replaceRisk:none`，不破坏原生 UI）。
- 画布：复用现有手写 SVG 力导向画布引擎（pan/zoom、节点拖拽、rAF），扩展出**有向连线、连接点、边标签、文件气泡、Apple 级动画**。
- 发布：独立 npm 包 + GitHub 仓库（MIT 许可，OIDC Trusted Publishing），上传至公司 `EaveBounty` 账号。
